# drift — Build Plan

Goal: a working, evaluated, demo-able framework that flags suspicious capability drift between
consecutive versions of open source packages. Start with **npm**, then prove the plugin model with
**PyPI**, with **crates.io (`build.rs`/proc-macros)** as a stretch goal.

Showcase outputs at the end: public repo, architecture diagram, evaluation numbers
(detection rate on known incidents, false positives per 1,000 benign updates, static vs dynamic
vs combined ablation, median time-to-verdict), demo video, and a technical blog post.

---

## 1. Core concepts

**ArtifactPair**: (ecosystem, package, `old_version`, `new_version`), plus fetched tarballs and,
where resolvable, the source repo at the matching tag/commit. `old` is **unset** when the package is
newly introduced as a dependency ("new-package mode": analyzers report absolute capabilities instead of a diff).

**Execution context**: when code runs, which drives severity.
| Context | npm | PyPI | crates.io |
|---|---|---|---|
| INSTALL | `preinstall`/`install`/`postinstall`/`prepare` scripts | `setup.py` (incl. `cmdclass`), build backends, `.pth` files | `build.rs`, proc-macros (compile time) |
| IMPORT | top-level code of `main`/`exports` entry files | module top-level code, `__init__.py` | n/a (no import-time execution) |
| CALL | everything else | everything else | everything else |

**Capabilities** (static, per file): `NETWORK`, `PROCESS_SPAWN`, `FS_SENSITIVE_READ`
(`~/.ssh`, `~/.aws`, `.npmrc`, `.pypirc`, browser profiles, wallets), `ENV_ACCESS`,
`DYNAMIC_CODE` (`eval`, `new Function`, `vm`, `exec`, `compile`), `OBFUSCATION`
(high-entropy literals, long encoded blobs, decode-then-exec chains), `NATIVE_BINARY`
(new `.node`/`.so`/`.dll`/executables), `CRYPTO_WALLET` (address-replacement patterns), `INSTALL_HOOK`.

**Behaviors** (dynamic, per run): normalized DNS queries, connection attempts (host/IP/port),
files read/written outside the package dir, executed commands, env vars read.

**Dependency drift**: dependencies added, removed or re-pointed between `old` and `new` — including
`dependencies`, `optionalDependencies`, `peerDependencies` and bundled deps for npm, `Requires-Dist` for PyPI.
Each **newly added** dependency is analyzed recursively in new-package mode (bounded depth and fan-out),
and its findings roll up into the parent's report. This catches payloads hidden in a new dependency
(axios → plain-crypto-js, event-stream → flatmap-stream, TanStack's malicious optionalDependencies).

**DriftFinding**: something present in `new` but absent in `old`, with capability/behavior,
context, evidence (file + line or trace event), and source analyzer.

**DriftReport**: all findings (own + rolled-up dependency findings) + metadata signals + score +
verdict (`BENIGN` / `REVIEW` / `SUSPICIOUS`) + a human-readable explanation.

## 2. Proto schema (starting draft, `proto/drift/v1/`)

Refine as needed, but keep the shape: one shared `Analyzer` service, versioned package.
Go and Python stubs are generated by `buf` into `gen/`; Rust types come from `tonic-build` in `crates/drift-proto`.

```proto
syntax = "proto3";
package drift.v1;

enum Ecosystem { ECOSYSTEM_UNSPECIFIED = 0; NPM = 1; PYPI = 2; CRATES = 3; }
enum ExecContext { EXEC_CONTEXT_UNSPECIFIED = 0; INSTALL = 1; IMPORT = 2; CALL = 3; }
enum Capability {
  CAPABILITY_UNSPECIFIED = 0; NETWORK = 1; PROCESS_SPAWN = 2; FS_SENSITIVE_READ = 3;
  ENV_ACCESS = 4; DYNAMIC_CODE = 5; OBFUSCATION = 6; NATIVE_BINARY = 7;
  CRYPTO_WALLET = 8; INSTALL_HOOK = 9;
}
enum Verdict { VERDICT_UNSPECIFIED = 0; BENIGN = 1; REVIEW = 2; SUSPICIOUS = 3; }

message PackageVersion {
  Ecosystem ecosystem = 1;
  string name = 2;
  string version = 3;
  string tarball_path = 4;      // local path inside shared volume, read-only
  string tarball_sha256 = 5;
  string repo_path = 6;         // optional checkout at matching tag/commit
  string repo_ref = 7;
}

message ArtifactPair {
  string job_id = 1;
  PackageVersion old = 2;       // unset => new-package mode (newly added dependency)
  PackageVersion new = 3;
  string parent_job_id = 4;     // set for dependency sub-jobs
  uint32 depth = 5;             // 0 = the package being updated
}

message Evidence {
  string file = 1;
  uint32 line = 2;
  string snippet = 3;           // truncated, max 200 chars
  string trace_event = 4;       // normalized dynamic event, if dynamic
}

message DriftFinding {
  string analyzer = 1;          // e.g. "static-rs", "trace-rs", "meta-go"
  string kind = 2;              // e.g. "capability_added", "new_dns_query", "tarball_only_file", "dependency_added"
  Capability capability = 3;
  ExecContext context = 4;
  repeated Evidence evidence = 5;
  double confidence = 6;        // 0..1, analyzer's own confidence
  map<string, string> attrs = 7;
  string via_dependency = 8;    // set when rolled up from a dependency sub-job (e.g. "plain-crypto-js@4.2.1")
}

message AnalyzeResponse {
  repeated DriftFinding findings = 1;
  repeated string errors = 2;   // non-fatal analyzer errors
  uint64 duration_ms = 3;
}

service Analyzer {
  rpc Analyze(ArtifactPair) returns (AnalyzeResponse);
  rpc Info(InfoRequest) returns (InfoResponse);   // name, version, supported ecosystems
}
message InfoRequest {}
message InfoResponse { string name = 1; string version = 2; repeated Ecosystem ecosystems = 3; }

message DriftReport {
  ArtifactPair pair = 1;
  repeated DriftFinding findings = 2;
  double score = 3;
  Verdict verdict = 4;
  string explanation = 5;       // human-readable summary
  repeated string fired_rules = 6;
}

service Scorer {
  rpc Score(ScoreRequest) returns (DriftReport);
}
message ScoreRequest { ArtifactPair pair = 1; repeated DriftFinding findings = 2; }
```

## 3. Component specs

### orchestrator (Go, `orchestrator/`)
- **Ingest** (`internal/ingest/npm`, later `pypi`): given `ecosystem/name` and optional version pair, resolve
  versions from the registry packument (npm) / JSON API (PyPI), download tarballs, verify integrity hashes,
  store them content-addressed (`internal/store`) in a shared volume (read-only to analyzers).
- **Repo resolution** (`internal/repo`): read `repository` / project URLs, clone shallowly, and try tags
  `vX.Y.Z`, `X.Y.Z`, `name@X.Y.Z`; record `repo_ref` or "unresolved".
- **Jobs** (`internal/jobs`): queue (start with an in-process worker pool backed by SQLite/Postgres; NATS optional
  later), fan out to registered analyzers via gRPC with per-analyzer timeouts, collect findings, call the scorer,
  and persist the `DriftReport`.
- **Dependency expansion**: when `static-rs` reports `dependency_added` findings, enqueue a sub-job per new
  dependency in new-package mode (`parent_job_id`, `depth+1`). Limits: max depth 2, max 20 sub-jobs per parent,
  cache verdicts by `(ecosystem, name, version)`. Sub-job findings are rolled up into the parent with
  `via_dependency` set before scoring.
- **Analyzer registry** (`internal/registry`, `config/analyzers.yaml`): analyzer gRPC endpoints; call `Info` on startup.
- **Dynamic runner** (`internal/dynamic`): invoke ossf/package-analysis for each version (verify its current
  integration surface first; prefer its analysis container image), collect raw JSON results, hand them to `trace-rs`.
  Keep it behind a Go interface so it's swappable.
- **API** (`internal/api`, `web/`): `POST /jobs`, `GET /jobs/{id}`, `GET /reports/{id}`, `GET /reports?verdict=`;
  plus a minimal server-rendered dashboard.
- **CLI** (`cmd/drift`): `drift analyze npm <pkg> --from X --to Y` for local runs.
- **Watch mode** (`internal/watch`, later milestone): seed a top-N list (npm downloads API), detect new versions
  (verify whether the registry changes feed is still available; otherwise poll packuments on an interval),
  and enqueue pairs automatically.

### safe-unpack (Rust library, `crates/safe-unpack/`)
- Streaming tar/gzip/zip/wheel extraction with limits on total bytes, per-file bytes, compression ratio,
  file count and path depth; rejects `..`, absolute paths, symlinks/hardlinks escaping root, and device files.
- `tests/attacks/` holds one crafted archive per attack case; `fuzz/` holds `cargo-fuzz` targets.

### static-rs (Rust service, `crates/static-rs/`)
- **Tree diff** (`tree_diff.rs`): added/removed/modified files between versions; flag new native binaries and new
  install hooks (`package.json` scripts diff; `setup.py`/`pyproject.toml` diff).
- **Tarball-vs-repo diff** (`tarball_vs_repo.rs`): files present in the published tarball but absent from (or
  different than) the repo at the matching ref, ignoring known build outputs via a per-ecosystem allowlist
  (e.g. `dist/`, minified bundles) — lower confidence when the repo ref is unresolved.
- **Dependency diff** (`depgraph.rs`): compare declared dependencies of `old` vs `new` (all dependency types listed
  in §1); emit `dependency_added` / `dependency_repointed` findings (git URLs, tarball URLs, aliases like
  `npm:other-pkg`) with the declared spec in `attrs`. The orchestrator turns `dependency_added` into sub-jobs.
- **Capability extraction** (`capabilities/`, tree-sitter queries in `capabilities/queries/*.scm`): JavaScript/TypeScript
  first, then Python → per-file capability set with evidence lines. Use import/require resolution plus call-pattern
  queries, not regex alone.
- **Execution-context mapping** (`context.rs`): determine which files are reachable from install hooks and entry points
  (simple static import graph); assign each capability the strongest context that reaches it.
- **Obfuscation signals** (`obfuscation.rs`): Shannon entropy of string literals, long base64/hex blobs,
  `Buffer.from(...,'base64')` / `atob` / `base64.b64decode` flowing into `eval`/`exec`/`Function`, and minified code in
  files that weren't minified before.
- **Output**: in diff mode, only capabilities/context new in `new`; in new-package mode, all capabilities.

### trace-rs (Rust service, `crates/trace-rs/`)
- Parse package-analysis result JSON for both versions.
- **Normalize**: strip temp-dir prefixes, PIDs, timestamps, random names; collapse registry/CDN traffic and
  package-manager internals; canonicalize paths to `$PKG`, `$HOME`, `$TMP`.
- **Baseline**: build a per-ecosystem noise model from benign install runs (event frequency), and suppress events
  seen in more than X% of benign runs.
- **Diff**: emit new DNS names, new IPs/ports, new commands, new sensitive-path accesses, new env reads, each with
  the phase (install/import) it occurred in.

### meta-go (Go service, `analyzers/meta-go/`)
- Maintainer set changed between versions; new publisher account.
- Publish-time anomalies: unusual hour/day for this package, long dormancy then a sudden release, multiple releases in
  minutes, and burst publishing across many packages by the same account.
- Version published with no corresponding repo tag/commit; repo archived but new version published; provenance
  present vs absent compared with previous releases (presence alone is **not** treated as proof of safety).
- Big version jump or semver-odd release.
- For newly added dependencies: package age, download count, and whether its maintainers overlap with the parent's.

### scorer (Python, `scorer/`)
- **Rule engine first** (`rules/default.yaml`, each rule with id, condition and weight); explainable output listing fired rules.
- Starter rules (tune in evaluation):
  | Rule | Weight |
  |---|---|
  | New `INSTALL_HOOK` that wasn't present before | high |
  | `NETWORK` or `PROCESS_SPAWN` newly reachable at INSTALL | high |
  | `FS_SENSITIVE_READ` or `ENV_ACCESS` + `NETWORK` both new (exfil pattern) | critical |
  | `OBFUSCATION` new + `DYNAMIC_CODE` new in same file | high |
  | Dynamic: new DNS/connection during install not in baseline | high |
  | Tarball-only file that is reachable at INSTALL/IMPORT | high |
  | New dependency whose own analysis shows INSTALL-context `NETWORK`/`PROCESS_SPAWN`/`OBFUSCATION` | critical |
  | New dependency that is very new or barely downloaded (meta) | medium |
  | Dependency re-pointed to a git/tarball URL or alias | medium |
  | Maintainer change + any high finding | multiplier |
  | New `NATIVE_BINARY` | medium |
  | Capability added only at CALL context | low |
- Verdict thresholds configurable; explanation is a short natural-language summary built from fired rules + evidence,
  naming the dependency when a finding came `via_dependency`.
- **Later**: an optional learned model (gradient boosting on finding features) compared against rules in the ablation.

### eval (Python, `eval/`)
- **Manifests** (`eval/manifests/`, committed, metadata + hashes only):
  `positives.yaml`, `hard_negatives.yaml`, `routine.yaml`, `synthetic.yaml`. Fields per pair: ecosystem, package,
  benign version, target version, `case_type` (`update_compromise` / `dependency_injection` / `ci_pipeline` /
  `destructive` / `new_malicious_package` / `synthetic`), payload context (install/import/call), technique tags
  (exfil, dropper, miner, wallet, worm), provenance present (y/n), incident date, source URL(s), expected tarball
  sha256/sha512, and `sample_available` (y/n).
- **Positives**: real malicious updates of legitimate packages paired with the last benign version. Aim for variety of
  payload context (install-hook, dependency-injected, import/call-time). Sample sources, in order:
  1. Research datasets with real tarballs: Backstabber's Knife Collection (free on GitHub), DataDog
     `malicious-software-packages-dataset` (encrypted zips), MalOSS, DONAPI, Maltracker; MalwareBench (Socket) on request.
  2. Downstream registry mirrors / npm-backed CDNs that still serve removed versions.
  3. Hash lookups on MalwareBazaar / VirusTotal using IOCs from vendor write-ups (Socket, StepSecurity, Snyk, Aikido, Wiz, Microsoft).
  4. Direct requests to vendors/researchers.
  Every recovered file is verified against the advisory hash before use. Metadata: OSV `MAL-` entries,
  ossf/malicious-packages, GitHub malware advisories. Benign predecessors come from the registry.
  When no sample is obtainable, keep the case as **metadata-only** (evaluated by meta signals only, reported in its
  own row) and check OpenSSF package-analysis public BigQuery results for publish-time dynamic traces.
  Never reconstruct real payloads from write-ups; recreate the technique as a synthetic fixture instead.
- **Hard negatives**: legitimate updates that add scary-looking capabilities (binary downloaders such as esbuild,
  sharp, puppeteer/playwright, prisma; new node-gyp/native builds; husky `prepare`; telemetry; env-var config;
  registry/publish tooling reading `.npmrc`; big refactors; switch to bundled/minified output).
- **Routine negatives**: consecutive-version pairs from the top ~1,000 npm packages, stratified by size and release
  frequency; plus same-version reruns for dynamic noise calibration.
- **Synthetic** (`fixtures/`): one injected technique per variant (postinstall download-and-exec, decode→eval, env exfil
  over DNS, dependency swap) plus evasion cases (CI-only, time-bomb, anti-sandbox, runtime second stage) that are
  expected misses. All payloads target the sinkhole only.
- **Harness**: run the full pipeline per pair, store reports, then compute detection rate, FP/1,000 updates,
  precision/recall at thresholds, time-to-verdict, and the ablation (static-only / dynamic-only / meta-only / combined),
  reported **per `case_type`** and separately for real vs synthetic.
- Notebook producing the figures for the write-up.

## 5. Risks and mitigations
| Risk | Mitigation |
|---|---|
| package-analysis integration surface changed | Verify against its current repo first; wrap behind a Go interface so it's swappable |
| Dynamic traces too noisy → FP flood | Baseline suppression, phase-aware diffing, low weight for CALL-only static findings |
| Few update-compromise samples | Combine several datasets, mirrors and hash lookups; keep metadata-only cases; add synthetic fixtures; report each category separately |
| Malicious versions removed from registries | Archived copies from datasets/mirrors/hash repositories, verified against advisory hashes; benign predecessor from the registry |
| Dependency expansion explodes (large trees) | Depth ≤ 2, ≤ 20 sub-jobs per parent, verdict cache, only *newly added* deps are expanded |
